# Changelog

## 1.2.2

- Synced the docs with `chatbotx@1.23.0` and `chatbotx-mcp@1.23.0` (`upstream.json`). The CLI
  catalog lists 13 more `ads` commands. Two of them have misleading generated names:
  `ads find-by-campaigns <id>` deletes a campaign and `ads find-by-connections` disconnects one.
  The CLI skill documents two new command-name collisions (`channel-posts find-by-management`,
  `posts destinations-posting-schedule`). The MCP skill lists the new default tool
  `post_analytics_summary`.
- The OpenAI manifest now uses the same support, privacy and terms URLs as the Claude manifest
  (`https://chatbotx.io/contact/`, `/privacy/`, `/terms/`).
- `npm run check:openai-plugin` now checks the built package in `dist/openai` by default. Before,
  it checked the repository root and reported false errors.
- The Antigravity MCP server is now called `chatbotx` (was `mcp`), and the Grok manifest no longer
  has the non-standard `note` key.

## OpenClaw plugin 1.2.1

- Added an OpenClaw plugin package, `plugins/openclaw/`, published to ClawHub as the bundle plugin
  `@chatbotx/chatbotx` (`openclaw plugins install clawhub:@chatbotx/chatbotx`). It is generated by
  `npm run build:openclaw-plugin` and committed, ships both skills, and connects to
  `https://app.chatbotx.io/mcp/messages` with `auth: "oauth"` (sign in with
  `openclaw mcp login chatbotx`). `.github/workflows/clawhub-plugin-publish.yml` publishes it through
  ClawHub's reusable package workflow; CI fails when the package is stale or breaks a ClawHub
  bundle rule (one marker, no `openclaw.plugin.json`, OAuth server, PNG icon under 512 KiB).
- Every plugin now carries the same summary and description, kept in `scripts/manifest/brand.mjs`
  and written by `npm run sync:manifests`: root `plugin.json`, the Claude, Cursor and Grok plugins
  and marketplaces, Gemini, Antigravity, OpenAI and OpenClaw. CI runs `npm run check:manifests`.
- Bumped the pinned ClawHub skill publish workflow to `openclaw/clawhub@252a3f86` (2026-11-23).

## OpenAI plugin 1.0.0

- Added a dedicated OpenAI plugin package, built from `openai/` by `npm run build:openai-plugin`
  into `dist/openai/` and `dist/openai.zip`. It connects to `https://app.chatbotx.io/mcp/openai`
  with OAuth (dynamic client registration) and ships the `chatbotx-openai` skill, which covers only
  the 37 v1 tools (36 API tools plus `get_guide`).
- The builder excludes the CLI and `chatbotx-mcp` skills, `.app.json`, app references and hooks,
  verifies a clean extraction of the ZIP with the strict checker, and prints the SHA-256.
- The OpenAI checker now validates OAuth configuration, rejects secret fields in `mcp.json`, and
  scans every shipped skill file for `search_tools`/`call_tool`, API-key and CLI instructions,
  deferred v2 tools and tools outside the profile.

## 1.2.1

- Moved the Claude Code plugin to `plugins/chatbotx/`, the layout the Claude plugin directory
  references through `git-subdir`, so the repo's build scripts stay out of the plugin. Its skills are
  copied from `skills/` by `npm run build:claude-plugin` with only the portable frontmatter keys
  (`name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`), which every
  Claude surface accepts; CI (`.github/workflows/claude-plugin.yml`) fails when the copy is stale.
- The Claude plugin now connects to the Claude profile, `https://app.chatbotx.io/mcp/claude`: a
  fixed tool set with no `search_tools`/`call_tool`, where every tool that changes data is marked
  destructive. Requires the ChatbotX release that serves `/mcp/claude`. The `chatbotx-mcp` skill
  documents the difference; the default endpoint stays `/mcp/messages` everywhere else.
- Added the directory listing fields to the Claude plugin manifest: `displayName`, `icon`,
  `documentationUrl`, `supportUrl`, `privacyPolicyUrl` (now the final `/privacy/` URL) and
  `termsOfServiceUrl`. Dropped the `skills` list, which repeated the default `skills/` folder.
- The `chatbotx` skill declares `compatibility`: it needs a shell with the CLI (Claude Code,
  Cowork), not Claude chat.
- Rewrote the `chatbotx` and `chatbotx-mcp` skill descriptions to say when to use each skill (and
  to include the omnichannel chatbot keywords), so agents trigger them more reliably and ClawHub
  search finds them.
- Added `.github/workflows/clawhub-publish.yml`: publishes `skills/*` to ClawHub on merge to `main`
  through ClawHub's own reusable workflow. Needs the `CLAWHUB_TOKEN` repository secret.
- Added an Antigravity plugin: `.antigravity-plugin/plugin.json` (display name, logo, suggested
  prompts) and a root `mcp_config.json` pointing at the hosted MCP server via `serverUrl`.
  Install with `agy plugin install https://github.com/ChatbotXIO/chatbotx-agent`.

## 1.2.0

- Plugins now connect to the hosted ChatbotX MCP server (`https://app.chatbotx.io/mcp/messages`,
  Streamable HTTP) and sign in with OAuth in the browser. No API key prompt and no local Node.js.
  The Claude Code `userConfig.api_key` and the Cursor `CHATBOTX_API_KEY` variable are removed.
  Gemini uses `httpUrl`; Cursor's `mcp.json` now uses the `mcpServers` wrapper.
- Added a portable root `plugin.json` + `mcp.json` (Agent Plugins schema) so Codex and compatible
  hosts can install the repo as a plugin. The root `mcp.json` is no longer a stdio snippet.
- The stdio server (`npx -y chatbotx-mcp` + API key, Node.js 24+) is documented as the fallback for
  self-hosted instances, CI, and headless agents.
- `chatbotx-mcp` skill: OAuth setup and workspace binding, the `CONFIRMATION_REQUIRED` /
  `_confirm: true` approval flow, the `get_guide` meta-tool, and the Connections, Mini Apps, and
  Pipelines default tools (52 total).
- `chatbotx` skill: documented against CLI 1.17.1. Updated the renamed commands (`appointments
  cancel add`, `coupon-topics archive add`, `questionnaires duplicate add`), the new bot-field,
  contact custom-field, flow-stats reset, and ads conversion-rule/campaign commands, and trimmed
  the collision list to the five that still exist.
- README install table covers Claude Code, Claude.ai/Desktop, ChatGPT, Cursor, Codex, VS Code,
  Gemini CLI, Windsurf, OpenCode, and Grok.
- Claude plugin: added `privacyPolicyUrl`; `assets/logo.svg` no longer uses a `<style>` block, so
  the plugin directory accepts it as an icon.

- Added an upstream drift check (`scripts/upstream/`, `.github/workflows/upstream-drift.yml`,
  `upstream.json`): a daily job compares the live, published `chatbotx` CLI and the live
  `chatbotx-mcp` default tool set against the docs in `skills/`, and opens/closes a single
  `upstream-drift`-labeled issue when they disagree. Run locally with `npm run check:upstream`.
  This is tooling only — it does not change any skill's published content or `version:`.

## 1.1.1

- `chatbotx` skill: moved the per-command catalog to `skills/chatbotx/references/commands.md` and
  kept a one-line-per-group index in `SKILL.md`. The 1.1.0 note below announced this move, but the
  file did not ship until now.
- Default MCP and CLI skill configuration to `https://app.chatbotx.io/api`; SaaS users now provide
  only an API key. Self-hosted instances still set their explicit `/api` URL.

## 1.1.0

- Removed the root `SKILL.md`. Skills now live only under `skills/`, so `npx skills add
  ChatbotXIO/chatbotx-agent` lists both `chatbotx` and `chatbotx-mcp`, installs only the skill folder,
  and no longer needs `--full-depth`.
- `chatbotx` skill is CLI-only: the command catalog stays in `SKILL.md` (moved to `references/` in 1.1.1),
  agents discover flags with `--help`, and the skill auto-installs the CLI when it is missing.
- Both skills state when to switch to the other transport (MCP tools connected vs bulk/CLI work).
- Claude Code plugin now starts the ChatbotX MCP server and prompts for the API key and URL via
  `userConfig`, matching the Cursor, Grok, and Gemini manifests.
- README documents installs per agent (Claude Code, Cursor, Codex, Windsurf, Gemini CLI, Grok).
- Ignore local `npx skills add .` artifacts (`.agents/`, `.claude/`, `skills-lock.json`).

## 1.0.0

- Initial ChatbotX agent distribution repository.
- Published public `chatbotx` and `chatbotx-mcp` skills.
- Added a root `SKILL.md` (copy of `skills/chatbotx/SKILL.md`) so `npx skills add ChatbotXIO/chatbotx-agent` installs the CLI skill directly.
- Added Cursor, Claude Code, Grok, Gemini, and generic MCP manifests.
